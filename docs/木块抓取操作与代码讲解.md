# 地面木块抓取

最新版本默认末端倾斜 -60°，`--pitch-deg 0` 可恢复垂直姿态；下文保留前期修正过程，最新操作与相机性能说明见 [倾斜抓取与相机卡顿修正](倾斜抓取与相机卡顿修正.md)。

## 启动和操作

终端一运行（保持运行）：

```bash
cd /home/ubuntu/ghost_arm
./ghost.sh start gui:=true
```

在另一个终端运行：

```bash
cd /home/ubuntu/ghost_arm
./ghost.sh grasp pick
```

程序张开夹爪，利用已有解析逆运动学算出准备姿态，飞到木块上方，缓慢下降，夹紧，然后抬高 25 厘米。木块与夹爪之间没有固定关节，也不通过直接设置木块位置制造抓取动画；木块是否跟随由 Gazebo 接触和摩擦求解。

松开，让木块落地：

```bash
./ghost.sh grasp release
```

`release` 是张开后自由落地，不是先下降再轻放。松开后，若木块仍直立在初始位置附近，可以再次运行 `./ghost.sh grasp pick`。如果木块被推远、翻倒，或小球被手动移走，可以停止并重新启动仿真，恢复初始状态。程序不会自动重置或瞬移物块。

可选：`./ghost.sh view` 查看 RViz，`./ghost.sh camera` 查看底部相机。不要在自动抓取过程中同时操作关节滑块、遥控或另发导航命令。

## 模型与物理

`src/ghost_sim/simulation/wood_block.py` 定义木块，`create_scene.py` 在生成世界时调用它。

- `SIZE = (.04, .04, .06)`：长宽高为 4、4、6 厘米。
- `MASS = .04`：质量为 40 克。
- `POSITION = (.10, 0., .03)`：世界坐标，中心高 3 厘米，所以底面正好位于地面。
- `static=false`：物块参与动力学，可以被推动和抓起。
- `inertial`：设置质量和均匀长方体转动惯量，例如 `ixx=m*(y*y+z*z)/12`。
- `visual`：相机与界面显示的棕色木块外形。
- `collision`：与夹爪、地面发生接触的实体范围，尺寸与外观一致。
- `surface/friction/ode/mu` 和 `mu2`：两方向摩擦系数设为 1.5；手指也设置相同摩擦参数。
- `ApplyLinkWrench`：世界仍为零重力以支持现有幽灵悬浮方式，仅给木块持续施加 `Fz=-0.04*9.81=-0.3924 N` 的向下力，等效于木块自身受到地球重力。以后添加其他动态物体，也要为它们配置重量。
- `PosePublisher`：发布木块实际位姿，用于判断它是否真的抬起来，也供 RViz 动态显示。

官方插件说明：https://gazebosim.org/api/gazebo/6/classignition_1_1gazebo_1_1systems_1_1ApplyLinkWrench.html

## 抓取流程与边界

`src/ghost_sim/control/grasp_demo.py` 是此版本的演示控制器。

1. `ready()` 等待关节状态、小球和木块位姿以及命令桥就绪，取消之前的导航。
2. `pick()` 检查初始位置和朝向。这是原点附近、无障碍的小范围固定场景演示，不是任意位置的抓取规划。
3. `inverse_kinematics()` 列出解析逆解，`select_body_safe_solution()` 过滤会靠近或穿过球体的整条关节路径，使抓取中心到达相对于小球的 `(0, 0, -0.46)` 米，末端俯仰角为 0。
4. `joint_move()` 用三次平滑插值逐步发送关节目标；使用仿真时间，限制手臂名义关节速度，避免一步跳到目标角度。
5. `fly()` 通过 `/ghost/cmd_vel` 发布速度，用实际小球位置计算误差，逐渐接近目标。它只执行演示中的直接对准和升降，不提供机械臂全身避障。
6. 木块中心上方 1 厘米作为抓取中心，使手指末端高于地面，避免手指先撞地板。
7. 手指闭合目标为 0，但实体木块阻止其完全闭合。每侧实际位移约为 1 厘米，夹爪控制器持续施力形成夹持。
8. `contact=True` 允许闭合时达不到位置目标；随后检查两根手指都在预期夹持范围，再开始抬升。
9. 抬升后等待 3 秒仿真时间，根据木块实际离地变化以及与抓取中心的距离判断成功，保存到 `runtime/reports/wood_grasp_check.json`。
10. `release()` 张开手指并检查木块是否落回地面。

程序检查反馈超时、仿真时间重置和动作超时；退出时发送零飞行速度；发生错误时请求手臂保持测量到的当前角度，同时保留手指夹持目标，避免自动松开负载。与已有 IK 执行共享文件锁，防止两个命令同时驱动手臂。

**这一版利用仿真真实位姿对准木块，尚未使用深度相机识别木块或估计抓取姿态。** 底部相机已经能看到物块，视觉定位是后续可以替换的输入环节。

## 初版验证记录（未覆盖自碰撞，已由下面的修正补充）

原有 33 项单元测试通过。Gazebo 实际抓取中，木块中心由约 0.030 米升到 0.268 米，实际抬升约 23.8 厘米；两侧手指位移约 0.010 米，保持检查通过。松开后，木块中心回到约 0.030 米，落地检查通过。升高量略小于小球命令的 25 厘米，来自接触滑动和关节受力偏差。

运行报告分别保存为 `runtime/reports/wood_grasp_check.json` 和 `runtime/reports/wood_release_check.json`，每次成功进入验证阶段都会更新。

随后未重启仿真，执行松开后再次抓取：第二次实际抬升约 23.7 厘米，验证再次通过。

## 修正：机械臂避开球体

初版虽然能夹起木块，但验证只检查了夹持与抬升，遗漏了机械臂穿过球体。原目标存在两组逆解，按关节变化距离排序会选中肩角约 -1.37 rad、肘角约 +0.60 rad 的分支，上臂碰撞盒侵入半径 0.28 米的球体约 9.7 厘米。不能用末端位置正确来证明整条机械臂姿态正确。

现在抓取中心改为 `base_link` 下 `(0, 0, -0.46)` 米，选择肩角约 -0.664 rad、肘角约 -0.671 rad、腕角约 1.335 rad 的分支，机械臂先沿球体后方下垂，再向球底伸出。

新增 `src/ghost_sim/kinematics/body_collision.py`：

- `arm_body_clearance()` 按模型中真实关节原点、转轴、碰撞盒尺寸逐节计算位姿。将球心变换进每个连杆碰撞盒的局部坐标，用 `clip` 求盒上最近点，最近点距离减去球体半径得到间隙。负数代表穿入。
- 固定安装支架和底部安装板需要与球体连接，不按运动连杆处理；检查覆盖尾根转动件、上臂、前臂、掌部和两指。
- `check_body_path()` 沿关节空间直线插值，以最大关节增量 0.01 为采样分辨率，检查起点、中间姿态和终点，要求计划路径保留 5 毫米间隙。它是离散检查，不是数学上的连续碰撞证明。
- `select_body_safe_solution()` 按原先与当前姿态接近的顺序尝试所有逆解，只有整段路径通过检查才执行；没有这样的直接路径就报错，不自动规划绕行。
- 抓取和 `ik --execute` 执行中，实际关节姿态的球体间隙低于 2 毫米时停止动作。
- Gazebo 的运动连杆增加 `self_collide=true`，作为物理层的自碰撞约束。
- `arm ready` 和 `arm close` 的预设也同步更新，发送前检查路径。旧文档中的 `[0,-0.8,-0.6,1.4]` 仍可用于数学 FK 示例，但不再是当前准备姿态。

这里只做运动连杆与球体的几何路径筛选，未实现完整的机械臂与房间障碍物路径规划。纯数学 `ik` 仍会列出所有符合运动学的解；`--execute` 才筛选可执行的球体避碰路径。

新增回归测试覆盖旧分支穿球、新分支选择、起终点安全但中途碰撞、无效输入。单元测试共 37 项通过。

修正后重新启动 Gazebo 实测：完整抓取通过，木块实际抬升 0.2378 米；按实时关节状态计算，整段动作中运动连杆碰撞盒与球体的最小间隙约 0.02197 米（2.2 厘米），不再只依靠末端是否抬起判断成功。报告增加 `min_measured_body_clearance_m` 与 `body_path_check` 字段。

## 修正：长时间夹持后无法松开

现象是 `grasp release` 报“关节运动超时”，两根手指实际停在约 0.01 米。原因是 Fortress `JointPositionController` 未指定积分参数时采用 `i_gain=0.1`、积分项限幅 ±1。木块使手指无法达到闭合目标 0，长期存在约 0.01 米误差，积分项累积出持续夹紧力，张开指令需要很长时间才能抵消它。

手指控制器现在显式设置 `i_gain=0`、`i_max=0`、`i_min=0`，保留比例、微分控制和力限幅。约 0.01 米的夹持误差通过比例项产生约 0.3 N 的单侧夹紧力，不再随夹持时间积累。

可用实际 ignition-math PID 实现复现：

```bash
cd /home/ubuntu/ghost_arm
c++ tests/integration/check_finger_pid.cpp $(pkg-config --cflags --libs ignition-math6) -o /tmp/check_finger_pid
/tmp/check_finger_pid
```

该测试模拟手指被木块阻挡 1000 秒，再持续发送张开目标 80 秒。旧配置仍为 -0.43 N（夹紧方向），新配置为 +0.45 N（张开方向）。它验证控制器问题，不替代完整物理抓取测试。

原控制器实现：https://github.com/gazebosim/gz-sim/blob/ign-gazebo6/src/systems/joint_position_controller/JointPositionController.cc

若小球位于原点附近、木块在地面，`grasp pick` 现在允许从至少 0.40 米高度开始：先张开手指解除地面物块接触，再升至至少 0.80 米，随后调整机械臂并抓取。不再要求用户先手动升到 0.70 米。低于 0.40 米或离开演示区域仍会拒绝执行。

修改 SDF 控制器参数后必须重新启动仿真，仅重新打开 RViz 不会加载新参数。

修改后已重新启动 Gazebo，实际执行 `grasp pick` 和 `grasp release` 均通过；松开后木块中心回到约 0.0300 米。原有 37 项单元测试通过，长时间阻挡 PID 回归测试也通过。
