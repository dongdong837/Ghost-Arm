# 房间中的球形幽灵：第一阶段

Ubuntu 22.04 / ROS 2 Humble / Gazebo Fortress。独立项目，原小车文件保留在 `/home/ubuntu/robot_sim`。

当前实现：悬浮球体、双眼和嘴、XYZ 平移、绕 Z 转向、松键悬停、RGB-D 相机、RViz 房间与模型显示。已接入三维体素地图和三维自主导航（见后文第二、三阶段）；已接入大模型目标控制（见第四阶段）。不要使用原小车的 Nav2/AI 脚本控制幽灵。

三个终端依次运行（已经运行的不必重复启动）：

```bash
/home/ubuntu/ghost_sim/start_sim.sh
/home/ubuntu/ghost_sim/view_ghost.sh
/home/ubuntu/ghost_sim/teleop.sh
```

默认只启动 Gazebo 服务端，RViz 是主要观察窗口；需要 Gazebo 窗口时先结束已有仿真，再执行 `start_sim.sh gui:=true`。

键盘窗口须保持焦点；按住或连续按键：

| 按键 | 动作 |
| --- | --- |
| W / S | 房间固定坐标 +X / -X |
| A / D | 房间固定坐标 +Y / -Y |
| R / F | 升高 / 降低 |
| J / L | 左转 / 右转 |
| 空格 / K | 停止并悬浮 |
| Q / Ctrl+C | 停止并退出遥控 |

转向不会改变 W/S/A/D 对应的世界坐标方向。相机沿幽灵脸部的 +X 方向观察，转头会改变画面。单次按键最多持续 0.35 秒；控制命令中断 0.4 秒后飞行控制器发零速度。若飞行控制器本身被强制杀死，Gazebo 内置速度插件没有独立看门狗，请停止/重启仿真；这不是实机飞控。

场景零重力；球壳半径 0.25 米，碰撞球半径 0.28 米；初始球心高度 1.2 米；房间约 8×6×3 米。已知障碍的短距离预测停止不等于三维导航或未知障碍避障。

ROS_DOMAIN_ID=43，IGN_PARTITION=ghost_sim。通过脚本启动会自动设置，与小车的域 42 隔离。`/ghost/cmd_vel` 的 linear XYZ 是房间坐标速度，angular.z 是绕竖直轴角速度；下游 `/model/ghost/cmd_vel` 是经转换的模型坐标速度，不建议直接发布到下游绕过保护。

在初始中心空地、关闭键盘遥控后运行动作与相机自检（会实际移动幽灵）：

```bash
source /opt/ros/humble/setup.bash
ROS_DOMAIN_ID=43 python3 /home/ubuntu/ghost_sim/check_flight.py
```

关闭顺序：遥控 Q → 仿真 Ctrl+C → 关闭 RViz。修改模型后运行 `python3 /home/ubuntu/ghost_sim/create_scene.py`，再重启仿真与 RViz。

学习入口：[代码逐句讲解.md](代码逐句讲解.md)。文档包含各文件的解释、逐行对照及测试结果。

## 第二阶段：三维可飞行空间

已加入已知场景体素地图，**不是 SLAM/相机重建**。每格 0.1 米，范围 [-4,4)×[-3,3)×[0,3)，共 80×60×30 格。坐标系为 simulation_reference。

- 0：整个体素内的球心位置均满足幽灵半径 0.28 米＋余量 0.05 米的静态障碍间距。
- 1：本格无实体占据，但幽灵放在其中可能与障碍太近，禁止用于规划。
- 2：体素与实际碰撞几何相交或接触。
- 地图范围之外不可飞行，不将未知区域当作空闲。

`flight_space.npz` 保存 uint8 的 states[x,y,z] 与 metadata；`flight_space.json` 保存人可读元数据。数据来自 SDF collision，而非透明外观。生成器检查全部体素体积与障碍的距离，较只检查体素中心更保守。地图静态；修改场景后重启仿真/地图节点生成新地图，命令行查询会拒绝哈希不一致的旧地图。

默认 RViz 绿色薄片是高度 1.2 米所在层的可飞行区域（该层中心为 1.25 米）。切换高度：

```bash
source /opt/ros/humble/setup.bash
ROS_DOMAIN_ID=43 ros2 param set /ghost_voxel_map slice_height 0.5
ROS_DOMAIN_ID=43 ros2 param set /ghost_voxel_map slice_height 1.5
```

在 Displays 中可选开启 `Obstacle voxels (full room)`（橙红实体）、`Ghost clearance exclusion`（黄色间距禁区）、`Flyable voxels (all heights)`（青色所有可飞行体素）。完整图层较密，可能遮挡内部；日常保留高度切片即可。

查询一个 XYZ 球心位置：

```bash
python3 /home/ubuntu/ghost_sim/voxel_map.py --query -1.8 1.2 0.4
python3 /home/ubuntu/ghost_sim/voxel_map.py --query -1.8 1.2 1.5
```

这两个点在绿色箱子内部和上方，结果应分别不可飞行、可飞行。仅生成文件可直接运行 `python3 /home/ubuntu/ghost_sim/voxel_map.py`。

ROS `/ghost/map/voxels` 为全量 PointCloud2，每个体素一个中心点，字段 x/y/z(float32)、state(uint32)，发布保留消息；`/ghost/map/metadata` 为 JSON String。显示用四个 MarkerArray 话题与实际完整数据分开。下游需读取 state 判定可飞行，不能把 PointCloud2 中的所有点都当成障碍。

地图生成本身不执行路线搜索；第三阶段已加入规划与连续连线碰撞检查。键盘控制仍保留已有短距离停止保护。

## 第三阶段：三维自主导航

现在启动仿真会同时启动 `ghost_navigation3d`。输入的三个位置参数明确是 **X、Y、Z（米）**，朝向另外用 `--yaw`（弧度）指定：

```bash
# 飞到房间中心，高度 2.2 米：
/home/ubuntu/ghost_sim/navigate.sh 0 0 2.2
# 飞到箱子另一侧，高度 0.5 米：
/home/ubuntu/ghost_sim/navigate.sh 2.8 1.0 0.5
# 回到中心并朝左转 90 度：
/home/ubuntu/ghost_sim/navigate.sh 0 0 1.2 --yaw 1.5708
# 取消当前目标并悬停：
/home/ubuntu/ghost_sim/cancel_navigation.sh
```

RViz 粉色线为三维航线。CLI 会等待 SUCCEEDED/FAILED/REJECTED/CANCELED；Ctrl+C 请求取消。按键盘运动键会取消自动导航并接管，空格/K 会调用取消服务。键盘空闲时持续发送的零速度不会覆盖导航速度。修改前已打开的旧控制终端需退出重开，以加载空格取消逻辑。

规划器使用六邻接体素 A*，再做连续球体碰撞检查简化路线；跟踪器按 XYZ 误差发布世界坐标速度，经既有飞行控制器转换和保护。规划速度上限 0.28 米/秒，到达位置容差 0.06 米，最终朝向容差 0.10 弧度。定位中断、路径跟踪不安全、20 秒无位移进展或总时限 180 秒会停止并报告失败。

这是已知静态地图三维导航，不使用小车的二维 Nav2；当前没有动态障碍重规划；大模型控制见第四阶段。RViz 的二维目标工具不能指定高度，暂用上述命令行或 `/ghost/goal` 的 PoseStamped 目标（frame_id=simulation_reference）。

实测：升高到 2.2 米、下降到箱前、升高越过箱子再降到另一侧均成功，误差均小于 6 厘米；障碍内部目标被拒绝。结果见 `sensor_samples/navigation3d_validation.json`。代码逐句说明见教程第 16 章。

## 第四阶段：大模型控制三维目标

调用阶跃星辰 API，模型名默认 `step-1o-turbo-vision`。程序运行在本地，推理在云端，不是本地模型权重部署。沿用原终端中的 STEPFUN_API_KEY；新终端中可安全输入：

```bash
read -rsp 'StepFun API key: ' STEPFUN_API_KEY; echo
export STEPFUN_API_KEY
```

仿真已启动时执行：

```bash
/home/ubuntu/ghost_sim/ghost_ai.sh '飞到房间中心，高度2米'
/home/ubuntu/ghost_sim/ghost_ai.sh '升高半米'
/home/ubuntu/ghost_sim/ghost_ai.sh '降到1米'
/home/ubuntu/ghost_sim/ghost_ai.sh '飞到绿色箱子正上方'
/home/ubuntu/ghost_sim/ghost_ai.sh '回到房间中心'
/home/ubuntu/ghost_sim/ghost_ai.sh '停下'
```

`--dry-run` 调用真实模型并验证目标/路线，但不飞行。`--vision` 上传一帧幽灵实时相机图像，仅回答观察问题，不执行移动：

```bash
/home/ubuntu/ghost_sim/ghost_ai.sh '飞到绿色箱子正上方' --dry-run
/home/ubuntu/ghost_sim/ghost_ai.sh '看看前面有什么' --vision
```

高度指球心离地高度；相对升降基于模型回复后读取的真实位置。未指定朝向时保持当前 yaw。箱子上方的位置由本地 SDF 箱顶高度＋0.65 米生成，不是视觉识别测距。所有移动目标通过本地规划器验证，箱内、墙内、过高/过低目标会被拒绝，不会偷偷改到另一个位置。

配置文件 `ghost_ai_config.json` 只保存 API 地址和两个模型名，不含密钥。可用环境变量 STEPFUN_BASE_URL / STEPFUN_LLM_MODEL / STEPFUN_VISION_MODEL 覆盖。任务解析与目标记录见 `sensor_samples/ai_goal.json`，最终飞行结果仍见 `sensor_samples/navigation3d_result.json`；解析成功不等于飞行成功，应看到 SUCCEEDED。

明确的“停下/停止/悬停/取消/取消导航”直接调用本地取消服务，无需模型和密钥。键盘接管规则保持不变。一次只执行一个目标；多步骤、未登记地标或不明确的方向会要求澄清。详解见第 17 章。

真实阶跃 API 联调已通过：指定绝对高度、相对降低半米、飞到绿色箱子正上方均导航成功，位置误差小于 6 厘米。报告：`sensor_samples/ai_validation.json`。
