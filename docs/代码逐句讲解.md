# 球形幽灵仿真：代码逐句讲解

> 项目已按模块分类，当前入口为根目录 `ghost.sh`。目录迁移与路径解析见第 18 章和[目录说明](目录说明.md)；前面源码块为开发时快照。

本文对应独立项目 `/home/ubuntu/ghost_sim`。从模型到控制完整讲解，不需要先理解旧小车代码。每个 Python 文件的实际源码在文末逐行列出；正文按语句和代码块解释，续行属于同一句。行号仅用于对照，不要把行号复制进 Python。

## 1. 先理解我们做到了什么

幽灵不是把小车轮子藏起来：旧差速驱动已移除，模型只有一个主链接，使用三维速度控制。它能沿房间 X、Y、Z 三个方向移动，也能绕竖直轴转头。

已实现：球形外观、眼睛和嘴、悬浮、手动 XYZ 运动、转向、相机、TF、RViz、速度限幅、超时停止和已知障碍前方停止。没有实现：三维 A*、目标点自动导航、未知障碍建图、视觉物体三维定位、大模型指挥幽灵。原小车的二维 Nav2 与 AI 客户端没有复制进来，避免误把 yaw 当 z。

场景设为零重力，是理想悬浮机器人，不模拟旋翼、升力、电机或空气阻力。球壳半径 0.25 米，碰撞球半径 0.28 米，球心初始高度 1.2 米。眼睛朝本体 +X，转向会改变观察方向。

## 3. create_scene.py：从元素生成模型

### 3.1 导入与 XML 基础语法

`from pathlib import Path` 引入路径类。`import xml.etree.ElementTree as E` 引入 XML 读写库并简写为 E。`ROOT=Path(__file__).parent` 找到当前脚本目录，输出文件总写在项目中。

`def sub(parent, tag, text=None, **attrs):` 定义创建子元素的工具函数。parent 是父节点，tag 是标签，text 是正文，`**attrs` 收集属性，例如 `name='ghost'`。`E.SubElement(parent,tag,attrs)` 在父节点下添加 XML 元素。`if text is not None` 区分没有正文和数值 0；`str(text)` 把数字转成 XML 文本。`return node` 返回新节点，方便继续加子元素。

举例：`sub(ghost,'pose','0 0 1.2 0 0 0')` 对应 `<pose>0 0 1.2 0 0 0</pose>`；六个数依次是 x、y、z、roll、pitch、yaw，距离米、角度弧度。

### 3.2 visual()：画一个球

参数 link 是所属链接，name 是部件名，radius 是半径，pose 是相对链接位姿，color 是 RGBA。创建 `<visual name=...>` 后写 `<pose>`。嵌套的 `sub(sub(sub(...)))` 从内到外依次创建 geometry、sphere、radius，表示球体几何。

创建 material 后分别写 ambient 和 diffuse：环境光颜色与漫反射颜色。RGBA 最后一个数是透明度：1 不透明，0 完全透明。返回 visual 方便后续扩展。这个函数只画外观，不创建碰撞体或质量。

`plugin(parent,filename,name)` 拼接 Gazebo 插件库名与 C++ 类名。例如 velocity-control 对应 `ignition-gazebo-velocity-control-system`，类名为 `ignition::gazebo::systems::VelocityControl`。

### 3.3 build()：保留房间，删除旧车

`E.parse(ROOT/'room_template.sdf').getroot()` 读取素材 SDF。`find('world')` 找到世界，`world.set('name','ghost_room')` 设置新世界名。

查找 gravity 节点，没有则创建，然后设置 `'0 0 0'`。实测本机 Fortress/DART 仅设置 link 的 gravity=false 仍会下落，因此直接使用零重力世界。其他物体都为 static，不需要重力来支撑；以后添加动态可掉落物体时必须重新设计重力与悬浮力，不能沿用零重力假设。

`list(world.findall('model'))` 先复制模型列表，使遍历时删除元素不会漏项。`model.findtext('static') != 'true'` 识别非静态模型并移除，这一步删除原小车及其轮子、传感器和差速插件。

对 north/south/east/west 四面墙，读取 pose，用 split 分成六段，将第 3 个数（索引 2，z）改为 1.5。然后遍历碰撞与外观中的 box/size，把高度改为 3.0。墙中心高 1.5 米、高度 3 米，覆盖地面至天花板。左右墙和前后墙的原长宽保持不变。

### 3.4 天花板与球体

创建 `ceiling` 静态模型，中心高 3.05 米，厚 0.1 米，因此内侧下表面高 3 米。`for kind in ('collision','visual')` 为同一长方体分别创建实体碰撞与可见外观。材质透明和 transparency 只改变显示，不改变碰撞。

创建 `ghost` 模型，初始 pose=(0,0,1.2,0,0,0)。创建 `base_link`，没有单独偏移，因此球心就是模型原点。gravity=false 表明链接的设计意图；实际还通过前述世界零重力保证。

inertial/mass=1.0 指质量 1 千克。inertia 的 ixx/iyy/izz=0.03136，来自实心球惯量 `I=2/5*m*r²`，r=0.28；ixy/ixz/iyz=0 表示对称球交叉惯量为零。for 循环写入六项。

`sphere_collision` 是半径 0.28 米的碰撞球。`ghost_body` 外观半径 0.25 米，淡蓝半透明。碰撞球略大，用来包住脸部外观并留出空间。

循环创建左右眼：名字 left/right，y 分别为 ±0.075。白眼球 x=0.225、z=0.05、半径 0.035；深色瞳孔 x=0.253、半径 0.016，更靠前。f-string 中 `{y}` 将当前眼睛的 y 值写进 pose。嘴是前下方的小深色球，只承担显示作用。所有面部结构都属于同一个 base_link，没有关节。

### 3.5 三维运动与真实位姿插件

`VelocityControl` 接收 `/model/ghost/cmd_vel`，初始 linear/angular 都是 0。它直接设置模型线速度、角速度，不是差速驱动，也不模拟电机。[官方接口说明](https://gazebosim.org/api/gazebo/6/classignition_1_1gazebo_1_1systems_1_1VelocityControl.html)。速度使用本体坐标，飞行控制器会把房间坐标命令转换后再送入。

`PosePublisher` 将真实物理位姿发布出来。publish_link_pose 发布链接，publish_model_pose 和 publish_nested_model_pose 覆盖当前 Fortress 所需的模型位姿发布配置；use_pose_vector_msg 使用一条消息打包多个位姿；update_frequency=50 为目标仿真更新频率。

### 3.6 RGB-D 相机和输出文件

sensor 的 type=rgbd_camera，同时生成彩色、深度和点云。pose 的 x=.29 使光心位于脸前方，避免镜头看到自己的球壳；topic=/camera 是话题前缀。always_on=true 持续开启，update_rate=5 表示每仿真秒约 5 帧。

camera/horizontal_fov=1.047... 是水平 60°视场。optical_frame_id 指定图像光学坐标系。image 中 width=320、height=240，format=R8G8B8 是三通道 RGB。clip/near=.1、far=8 表示相机近远裁剪范围。

`E.indent(sdf)` 美化 XML 缩进；ElementTree.write 写成 ghost_room.sdf，encoding=unicode 输出文本，xml_declaration=True 写 XML 声明。

接着创建 URDF `<robot name='ghost_display'>` 和 `<link name='base_link'>`。遍历刚才生成的每个 visual：复制名字，把 SDF 六分量 pose 拆成 URDF origin 的 xyz/rpy；复制球半径；复制 diffuse 颜色到 URDF color/rgba。URDF 不复制物理插件，只供 RViz 显示。最后输出 ghost_display.urdf。

`if __name__ == '__main__': build()` 只在直接执行脚本时生成文件，被其他程序导入时不自动覆盖场景。修改生成器后要重新生成，并重启仿真和 RViz。

## 4. flight_control.py：从 XYZ 命令到悬浮运动

### 4.1 模块和旋转矩阵

math 提供三角函数；time.monotonic 提供不随系统调时跳变的计时；Path/ET 读取障碍；numpy 处理向量和矩阵；rclpy 运行 ROS 节点。Clock/ClockType 用于稳态计时器；SignalHandlerOptions 让程序先发停车再退出。Twist 是速度消息，TFMessage 接收 Gazebo 真实位姿。

`rotation(q)` 取四元数 x,y,z,w，构造 3×3 旋转矩阵 R。返回数组的三行就是将单位四元数展开后的标准公式；R 把本体向量转换到世界坐标，转置 `R.T` 把世界向量变回本体坐标。这里使用仿真提供的单位四元数。

### 4.2 初始化与障碍数据

`rclpy.init(signal_handler_options=SignalHandlerOptions.NO)` 初始化通信，同时保留 Python 默认 Ctrl+C 异常处理。创建 ghost_flight_control 节点。output 发布下游本体速度，队列长度 1，不积压旧速度。

state 保存四项：command=[vx,vy,vz,yaw_rate]、received 最后收命令的实际时间、pose 最新真实姿态、pose_time 最后收姿态时间。初始速度为零，姿态为空。

遍历 ghost_room.sdf 的静态模型，用 pose 的前三个数建立中心向量 c，用 visual/geometry/box/size 除以 2 得到半尺寸 h。当前墙、地板、天花板、箱子均是无旋转长方体，所以可这样检查。未来加入旋转障碍或其他形状时必须扩展。

### 4.3 receive(msg)：处理手动输入

把 linear.x/y/z 和 angular.z 放入四维 numpy 数组。`np.isfinite(...).all()` 判断全是有限数，否则整条命令置零。`np.linalg.norm(command[:3])` 求三维线速度模长，超过 .45 米/秒则同比例缩小，保持方向不变。

`np.clip(command[2],-.35,.35)` 限制升降速度；`np.clip(command[3],-.8,.8)` 限制转头角速度。`state.update` 同时存储限幅结果与接收时间。

### 4.4 poses(msg)：处理定位

TFMessage 中有多个位姿。只取 child_frame_id 为 ghost 的模型世界位姿，把 transform 与实际接收时间保存，随后 break 结束循环。这里用于控制的模型原点与 base_link 重合，不能盲目换成一个有局部偏移的链接位姿。

### 4.5 tick()：每 50 毫秒更新速度

创建空 Twist，默认六个速度都是零。读取单调时钟。只有已有姿态且收到它还不到 .5 秒时才进行非零控制，否则本轮发布零速度。

读取 pose 和 R。若命令新于 .4 秒则复制使用，否则使用四维零向量。这样键盘程序退出、断开或被杀死后，只要 flight_control 仍运行，就会自动停下。

p 是当前位置。`predicted = p + command[:3]*.3` 预测沿当前速度前进 .3 秒后的球心。

对每个箱体计算 `abs(predicted-c)-h`；负值说明该轴仍在箱体内，`maximum(...,0)` 把这些分量归零；求范数得到球心到箱体的距离。小于 .33 米则把三维平移速度置零。这相当于 0.28 米碰撞半径外再留 5 厘米余量。这里只短距离预判，不找绕路路线，也不感知地图之外新出现的物体。触发停止后可以反向离开。

`body = r.T @ command[:3]` 将期望的世界 XYZ 速度转为模型 XYZ 速度。`@` 是矩阵乘法。把三个分量转成 float 后写入 Twist.linear。转头后按 W 仍向房间 +X，而不是跟着脸部转向；这是此版本特意选择的控制方式。

roll 通过 `atan2(R[2,1],R[2,2])` 求得，pitch 通过 `asin(-R[2,0])` 求得；clip 防止浮点误差导致 asin 超域。`[-2*roll,-2*pitch,command[3]]` 是近水平姿态下的简单调平角速度，加上用户绕世界竖直轴转头速度；再乘 R.T 转到本体。不是支持任意大姿态的无人机飞控。

最后无论是否满足定位条件，都 `output.publish(msg)`，因此缺定位时也发送零指令。

### 4.6 订阅、时钟与退出

`/ghost/cmd_vel` 是对外世界坐标速度接口；`/simulation/ground_truth/poses` 是真实位姿输入。`create_timer(.05,...,clock=Clock(STEADY_TIME))` 每实际 50 毫秒执行，即使仿真暂停，也继续让旧命令过期。一般 ROS 节点使用 use_sim_time，但看门狗刻意使用实际单调时间。

`rclpy.spin(node)` 持续处理订阅与定时器。KeyboardInterrupt 捕获 Ctrl+C。finally 连续五次发零速度，每次间隔 .02 秒，随后销毁节点并 try_shutdown。

保护边界：Gazebo 内置 VelocityControl 会保持最后命令；如果 flight_control 自身遭遇 SIGKILL，看门狗也无法运行。此时应停止/重启仿真。第一阶段没有声称具备独立于控制进程的硬件级安全停止。

## 5. keyboard.py：键盘逐句解释

select 检查标准输入是否可读；sys.stdin 是当前终端；termios 保存/恢复终端属性；tty 进入无需回车的逐字符模式；time 用于按键超时。ROS 导入与飞行控制一致。

main 初始化 ROS、创建 ghost_keyboard 节点，在 `/ghost/cmd_vel` 发布 Twist。`termios.tcgetattr(sys.stdin)` 保存当前终端设置，退出时恢复，防止退出后终端不回显。

bindings 字典将每个键映射到 `(vx,vy,vz,yaw_rate)`：w/s 为 ±X 的 .3 米/秒，a/d 为 ±Y；r/f 为 ±Z 的 .25 米/秒；j/l 为 ±.6 弧度/秒。所有方向是房间固定坐标。print 的字符串换行分段只是源代码排版，flush=True 立即显示说明。

values 初始全零，last=0。try 中 `tty.setcbreak` 启用即时按键。while 检查 ROS 是否有效；`select.select([sys.stdin],[],[],.05)[0]` 最多等 50 毫秒，返回可读输入列表。

`read(1).lower()` 读取一个字符并转小写。q、Ctrl+C 字符 `\x03`、输入结束空字符串都退出循环。其他字符用 bindings.get 查表，未定义键（包括空格/k）得到零向量，同时更新 last。

如果 .35 秒没有新按键，values 归零。每轮创建 Twist，map(float,values) 把数值转为 ROS 要求的浮点数，写入并发布。因此按住或连续按键才能持续飞行；系统键盘自动重复延时可能使刚按住时短暂停顿。

except 处理 Ctrl+C；finally 连续发零速度、恢复终端原属性，销毁节点并关闭 ROS。`if __name__...` 是直接执行入口。

## 6. sim.launch.py：把所有节点接起来

Path 定位文件；LaunchDescription 收集启动动作；DeclareLaunchArgument 声明用户可选参数；ExecuteProcess 启动普通进程；OpaqueFunction 在运行时读取参数；LaunchConfiguration 获取参数值；Node 启动 ROS 软件包里的节点。

ROOT 是启动文件目录。`static_tf(...)` 接收父子坐标系、平移三元组和旋转三元组，默认旋转全零；拆包后构造 static_transform_publisher，将数值转成命令行字符串。frame-id 是父坐标，child-frame-id 是子坐标。

`generate_launch_description` 是 launch 的入口。内部 gazebo(context) 根据 gui 参数构造 `ign gazebo -r -v 3`，-r 表示运行而非暂停，-v 3 为日志详细度；gui 不为 true 时追加 -s，仅启动服务端。再追加最终 SDF 路径并作为 ExecuteProcess 返回。

actions 首先声明 gui 默认 false，然后执行 gazebo 函数，再启动 robot_state_publisher。robot_description 读取生成的 URDF，use_sim_time=True 使用 `/clock`。

for 循环依次将 ground_truth_tf、reference_scene、cloud_frame、flight_control 加入启动动作；`--ros-args -p use_sim_time:=true` 是 ROS 参数，Python 节点初始化时接收。启动动作列表不是等待前一个完全就绪后才继续，因此各节点需能等待消息。

parameter_bridge 同时连接 ROS 与 Gazebo。桥接描述中 `]` 表示 ROS → Gazebo，`[` 表示 Gazebo → ROS。速度流向 Gazebo，位姿/clock/图像/深度/内参/点云流向 ROS。Twist 对应速度，Pose_V 对应 TFMessage，Image 对应 sensor_msgs/Image，PointCloudPacked 对应 PointCloud2。

remappings 将模型位姿在 ROS 端改名为 `/simulation/ground_truth/poses`，将原始点云改名 `/camera/points_raw`，供修正节点输出最终 `/camera/points`。

camera_mount 定义 base_link → camera_link 平移 (.29,0,0)。camera_optical 定义 camera_link → camera_optical_frame，roll=-π/2、pitch=0、yaw=-π/2，用来转换机器人 x前/y左/z上与光学 z前/x右/y下坐标约定。最后返回所有启动动作。

## 7. ground_truth_tf.py：为什么幽灵在 RViz 中跟着动

deepcopy 用于复制消息，避免改动原订阅对象。TFMessage 是输入类型，TransformBroadcaster 用于发送 TF。

main 创建 ROS 节点和广播器。receive(message) 用字典推导式将 child_frame_id 映射到对应变换，便于查找 ghost 和 ghost/base_link；缺任意项就等待下一条，不发布不完整姿态。

复制模型和链接变换后，设置模型父系 simulation_reference、子系 simulation_ghost；链接父系 simulation_ghost、子系 base_link。保留原始时间戳、完整三维平移和四元数，广播两条变换。

得到的链是 simulation_reference → simulation_ghost → base_link → camera_link → camera_optical_frame。房间固定，幽灵移动，相机刚性跟随。仿真真实定位不是 SLAM。create_subscription 接收位姿，spin 运行回调；finally 清理节点和 ROS。

## 8. reference_scene.py：显示房间而不是二维导航地图

Path/ET 读取 SDF；QoSProfile 与 DurabilityPolicy 配置保留最新消息；Marker/MarkerArray 表示一个形状与一组形状。

main 创建节点；qos depth=1、TRANSIENT_LOCAL 表示晚启动的 RViz 也能收到保留的场景。scene_pub 发布 `/simulation/reference_scene`。只读取 static=true 模型，跳过幽灵。

pose 六分量转换为 float；assert 要求后三个旋转角均为 0，明确当前发布器仅支持无旋转房间长方体。读取 visual 中的 box 尺寸和颜色。

每个 Marker 设置固定房间 frame、统一 namespace、递增 id；类型 CUBE，动作 ADD。设置中心、单位四元数 w=1、长宽高、RGB。天花板 alpha=.04、墙=.12，其余=.65，便于从房间外观察内部。透明只影响显示，不影响物理阻挡。

publish() 读取当前 ROS 时间，更新每个 marker 的时间戳并发布数组。create_timer 每 2 秒更新一次，并先立即调用一次 publish。spin 和 finally 负责运行、清理。

与小车不同，这里不发布二维 OccupancyGrid，避免让人误以为已有三维地图或导航。看到的房间是已知场景的显示。

## 9. cloud_frame.py：点云坐标标签

本机 Fortress 的 RGB-D 点云数值是 x前/y左/z上，但消息头可能写成 optical frame。修正节点订阅 `/camera/points_raw`，只将 header.frame_id 改为 camera_link，再发布到 `/camera/points`；不旋转点坐标，避免二次旋转。

QoSProfile(depth=1) 默认可靠传输，避免本机大点云消息在尽力传输时丢片严重。保留 publisher/subscription 引用；spin 接收回调；finally 清理。这是针对当前仿真版本已验证的处理，换传感器实现时要重新核对坐标，不能无条件复用。

## 10. 三个 shell 脚本逐句解释

共同的 `#!/usr/bin/env bash` 指定解释器；`set -e` 使准备命令失败时退出；source 加载 Humble；export ROS_DOMAIN_ID=43 保证三个终端通信一致。`"$(dirname "$0")"` 是当前脚本所在目录，带引号防止路径空格被拆分。

start_sim 另设置 IGN_PARTITION，让 Gazebo 和 bridge 处于相同分区。cd 到项目目录。`exec 9> /tmp/ghost_sim.lock` 打开锁文件到文件描述符 9；`flock -n 9` 非阻塞申请锁，已有实例时提示并退出。此锁由进程持有，文件存在不等于锁被持有，不需要删除文件才能再次启动。最后 exec ros2 launch 替换 shell，`"$@"` 原样转发 gui:=true 等参数。

view_ghost 的最后一行启动 rviz2，-d 指定 ghost.rviz，参数 use_sim_time=true 与 Gazebo 时间一致。

teleop 使用另一把 ghost_teleop.lock，避免运行两个键盘同时发冲突速度；最后 exec python3 启动 keyboard.py。它不自动启动仿真。

## 11. ghost.rviz：每类配置的意思

Panels 中 Displays 是显示列表，Views 是视角设置。Visualization Manager 管理三维窗口，Class 空值由 RViz 自己使用；Global Options.Fixed Frame=simulation_reference 表示房间不跟着幽灵移动，Background Color 设置深灰背景，Frame Rate=10 降低虚拟机负载。

Floating ghost 使用 RobotModel，Description Topic=/robot_description，Transient Local 保证晚订阅能收到模型描述；Visual Enabled 显示外观，Collision Enabled=false 不画额外碰撞球，但物理碰撞仍存在。

Room geometry 使用 MarkerArray，订阅保留的 `/simulation/reference_scene`。RGB/Depth Image 显示相机各自图像；深度最小/最大范围控制显示亮度，不修改真实深度数据。RGB-D cloud 使用 PointCloud2，默认关闭以减轻渲染；需要时勾选。

各 Topic 的 Reliability Policy 表示可靠或尽力传输；Durability Policy 表示是否保留给晚加入订阅者；History Policy=Keep Last 配合 Depth 指定队列长度。Enabled 控制是否显示，Name 是左侧名称。

Tools 保留 MoveCamera、Select、FocusCamera，不再保留小车的 2D Goal Pose，因为第一阶段没有目标导航器。Views.Current 选 Orbit，Distance=10 米，Yaw=.65、Pitch=.65 弧度，Focal Point=(0,0,1)，让视线关注房间中部。Window Geometry 指定初始窗口宽高。

## 12. check_flight.py：如何证明模型真的能飞

此脚本会移动幽灵，只在初始中心空地执行，并先关闭键盘控制。导入 json 保存报告、math 计算位移、Path 指定结果路径、time 控制实际等待；ROS 消息用于发速度与读真实位姿/相机。

state 保存当前 [x,y,z,yaw]；counts 分别计数 RGB 与深度有效图像。poses 回调只取 ghost 模型，使用四元数公式计算 yaw。camera(key) 返回一个回调函数，只有尺寸为 320×240 且数据非空才增加相应计数。

run(seconds,values=None) 在一段实际时间内持续 spin；如果提供速度，每 .05 秒发布一次；values=None 时不发布，专门模拟输入断开。并非让程序只 sleep，这样同时能接收真实位姿。

首先发零速度 3 秒等待连接，检查有姿态、初始平面位置在中心 .5 米内、高度 .8～1.6 米。再等 1 秒检查漂移少于 .02 米。

逐阶段测试：上升、下降、±X、±Y、转向、转向后世界 +X、返回 -X。每段运动 1.5 秒，再零速度 .2 秒。用 before/after 差值检查期望轴方向移动超过 .1 米（旋转阶段为弧度），非目标平移轴变化低于 .04 米。检查真实位置，不只是确认收到 cmd_vel。

随后发 .5 秒上升速度，再完全停止发布，等待看门狗触发；再比较 1 秒内漂移是否小于 .02 米。继续向上发命令，检查天花板保护把球心停在合理高度；再下降到约 1.25 米，并检查 RGB/深度各至少收到 5 帧。

将各阶段位移、失联漂移、顶部停止高度、相机帧数和最终位姿保存到 sensor_samples/flight_validation.json。finally 无论成功或断言失败都发零速度、关闭节点。失败日志见 sensor_samples/flight_check.log；报告只在全部断言通过后生成。

本测试不能证明任意障碍、任意初始位置都安全，只验证当前场景中的基本运动、转向后坐标关系、失联悬停、顶部限位和相机数据。

### flight_control.py

```text

003 | import time
004 | from pathlib import Path
005 | import xml.etree.ElementTree as ET
006 | import numpy as np
007 | import rclpy
008 | from rclpy.clock import Clock, ClockType
009 | from rclpy.signals import SignalHandlerOptions

012 |
013 |
014 | def rotation(q):
015 |     x,y,z,w = q.x,q.y,q.z,q.w
016 |     return np.array([[1-2*(y*y+z*z),2*(x*y-z*w),2*(x*z+y*w)],
017 |                      [2*(x*y+z*w),1-2*(x*x+z*z),2*(y*z-x*w)],
018 |                      [2*(x*z-y*w),2*(y*z+x*w),1-2*(x*x+y*y)]])
019 |
020 |
021 | def main():
022 |     rclpy.init(signal_handler_options=SignalHandlerOptions.NO)
023 |     node = rclpy.create_node('ghost_flight_control')
024 |     output = node.create_publisher(Twist,'/model/ghost/cmd_vel',1)
025 |     state = {'command':np.zeros(4),'received':0.,'pose':None,'pose_time':0.}
026 |     obstacles = []
027 |     for model in ET.parse(Path(__file__).with_name('ghost_room.sdf')).findall('world/model'):
028 |         if model.findtext('static') == 'true':
029 |             centre = np.array(list(map(float,model.findtext('pose').split()))[:3])
030 |             half = np.array(list(map(float,model.findtext('link/visual/geometry/box/size').split())))/2
031 |             obstacles.append((centre,half))
032 |
033 |     def receive(msg):
034 |         command = np.array([msg.linear.x,msg.linear.y,msg.linear.z,msg.angular.z])
035 |         if not np.isfinite(command).all():
036 |             command[:] = 0
037 |         speed = np.linalg.norm(command[:3])
038 |         if speed > .45:
039 |             command[:3] *= .45/speed
040 |         command[2] = np.clip(command[2],-.35,.35)
041 |         command[3] = np.clip(command[3],-.8,.8)
042 |         state.update(command=command,received=time.monotonic())
043 |
044 |     def poses(msg):
045 |         for pose in msg.transforms:
046 |             if pose.child_frame_id == 'ghost':
047 |                 state.update(pose=pose.transform,pose_time=time.monotonic())
048 |                 break
049 |
050 |     def tick():
051 |         msg = Twist()
052 |         now = time.monotonic()
053 |         if state['pose'] is not None and now-state['pose_time'] < .5:
054 |             pose = state['pose']; r = rotation(pose.rotation)
055 |             command = state['command'].copy() if now-state['received'] < .4 else np.zeros(4)
056 |             p = np.array([pose.translation.x,pose.translation.y,pose.translation.z])
057 |             # Short look-ahead stop, not route planning. Geometry is axis-aligned.
058 |             predicted = p + command[:3]*.3
059 |             if any(np.linalg.norm(np.maximum(np.abs(predicted-c)-h,0)) < .33 for c,h in obstacles):
060 |                 command[:3] = 0
061 |             body = r.T @ command[:3]  # Gazebo expects model-relative velocity.
062 |             msg.linear.x,msg.linear.y,msg.linear.z = map(float,body)
063 |             roll = math.atan2(r[2,1],r[2,2])
064 |             pitch = math.asin(float(np.clip(-r[2,0],-1,1)))
065 |             angular = r.T @ np.array([-2*roll,-2*pitch,command[3]])
066 |             msg.angular.x,msg.angular.y,msg.angular.z = map(float,angular)
067 |         output.publish(msg)
068 |
069 |     cmd_sub = node.create_subscription(Twist,'/ghost/cmd_vel',receive,1)
070 |     pose_sub = node.create_subscription(TFMessage,'/simulation/ground_truth/poses',poses,10)
071 |     timer = node.create_timer(.05,tick,clock=Clock(clock_type=ClockType.STEADY_TIME))
072 |     try:
073 |         rclpy.spin(node)
074 |     except KeyboardInterrupt:

076 |     finally:
077 |         for _ in range(5):
078 |             output.publish(Twist()); time.sleep(.02)
079 |         node.destroy_node(); rclpy.try_shutdown()
080 |
081 | if __name__ == '__main__':
082 |     main()
```

## 15. 用体素表示三维可飞行空间

本节是第二阶段新增实现。前面第一阶段的“尚无三维地图”描述保留为开发过程；当前已增加静态已知三维地图，仍未接入自主路径规划。

### 15.1 为什么需要三种状态

房间划分为边长 0.1 米的小立方体，数组 states[x,y,z] 有 80×60×30=144000 个单元。原点 (-4,-3,0)，上界 (4,3,3) 不包含在范围内。第 (i,j,k) 格中心为 origin + ([i,j,k]+0.5)*resolution。

状态 2 表示体素与实际碰撞体相交或接触；状态 1 表示几何上没有实体，但不满足幽灵球心需要的安全间距；状态 0 表示整个体素中的球心位置均满足间距。半径取 SDF 碰撞球的 0.28 米，再加 .05 米余量，总距离 .33 米。不是只把模型当作没有体积的点。

同一 XY 在绿色箱子内部不可飞行，箱顶附近仍有间距禁区，足够高才可飞行。这是三维地图区别于平面占据栅格的关键。高度切片只是观察手段，文件与 ROS 完整消息始终保留全部高度。

### 15.2 voxel_map.py 逐句解释

Path 定位项目；hashlib 给源 SDF 计算 SHA-256，检测地图是否过期；json 保存元数据；numpy 批量计算体素；ElementTree 读取 XML。FREE/CLEARANCE/OCCUPIED 分别定义数字标签 0/1/2。

`build(resolution=.1,margin=.05)` 的参数分别为格边长和额外余量。先检查有限数、分辨率大于零、余量非负。读取 ghost_room.sdf，设置房间内的固定范围 origin/upper。`rint((upper-origin)/resolution).astype(int)` 得到三轴格数；allclose 检查尺寸能被格边长整除，否则拒绝生成不一致的地图。

从 ghost/link/collision 的 sphere/radius 读取碰撞球半径，因此不是视觉球壳的 .25 米。`np.arange(shape[i])` 创建轴索引，加 .5 后乘分辨率、加原点得到各轴格心；meshgrid(indexing='ij') 保留 x/y/z 顺序，stack(axis=-1) 得到每格三个坐标。

occupied 初始全 false。blocked 的初值检查整个体素到地图上下边界的距离：球心不能贴着地图边界飞，超出范围的部分不被视为空闲。

遍历 static=true 的 model，再遍历 link/collision。解析三层 pose；各层 rotation 必须为零，否则显式拒绝。当前全部障碍都是轴对齐长方体；遇到其他静态几何也报错，不静默漏掉障碍。中心为三层平移之和，half 为长宽高的一半。boxes 将这些数据保存进元数据，便于测试和解释。

`delta = maximum(abs(centres-centre)-half-resolution/2,0)` 计算整个体素与箱体在三个轴上的最短分离距离。扣除半个格边长非常重要：若只检查格心，会把部分不安全的格子误标为可飞行。`norm(delta,axis=-1)` 得到体素与箱体最短欧氏距离。距离为零（容差 1e-9）则 occupied=true；距离小于半径加余量则 blocked=true。`|=` 表示保留之前障碍的结果并加入当前障碍。

两层 np.where 优先标实体 2，再标禁区 1，剩下为自由 0，转换成 uint8 减少存储。metadata 保存坐标系、分辨率、边界、数组顺序、碰撞半径、余量、状态含义、来源、哈希、计数、障碍箱体。`return states,centres,metadata` 同时提供数值和解释。

`save()` 调用 build，用 np.savez_compressed 写入 flight_space.npz，包含 states 和 JSON 字符串 metadata；另写缩进 JSON 方便人读，再返回三个结果。文件是压缩数组，不是图片。

`query(x,y,z)` 用 allow_pickle=False 读取数组与 JSON，避免依赖 Python 对象反序列化。重新计算当前 SDF 哈希，不一致就要求重新生成。检查输入有限、在半开地图范围内，越界返回 outside_map 且 flyable=false。`floor((p-origin)/resolution)` 将世界坐标映射为格索引，取标签，只有 FREE 才返回 flyable=true。

命令行 argparse 接收可选 `--query` 三个浮点数；有参数就查询，没有就生成地图并打印元数据。不需要 ROS 即可用此工具读写三维地图。

### 15.3 voxel_map_node.py 逐句解释

导入 rclpy/QoS 运行节点；Point/Marker/MarkerArray 供 RViz；PointCloud2/PointField 编码全量地图；String 发布 JSON 元数据。导入本地 save 与三个状态常量。

main 初始化节点 ghost_voxel_map，声明 slice_height 默认 1.2。调用 save 生成并保存地图。QoS depth=1、TRANSIENT_LOCAL、默认 Reliable，保留每个话题的最新消息，RViz 晚启动也能获得地图。

pubs 字典推导式为 obstacles、clearance、free_slice、free_volume 各创建一个 MarkerArray 发布器；另外发布 metadata 与 voxels。colours 定义橙红实体、黄色禁区、绿色切片、青色自由空间，最后一个数是透明度。

内部 `layer(name,points,scale)` 创建一个 CUBE_LIST marker。frame_id 使用地图坐标系，stamp 使用仿真时间，ns 按图层区分、id=0、action=ADD，因此后续消息替换同一图层而不累积。orientation.w=1 是无旋转单位四元数；scale 指单个显示方块尺寸。把 numpy 格心转成 ROS Point 列表，包进 MarkerArray 返回。

遍历三个完整状态图层，使用布尔索引 `centres[states==label]` 选出对应格心，显示方块边长 .095，比真实 .1 米略小以留出视觉间隙；这个显示间隙不改变地图标签。完整图层都发布，但 RViz 默认关闭，避免大量方块遮挡房间。

metadata 转为 JSON String 发布。packed 是结构化 numpy 数组：x/y/z 为小端 float32，state 为小端 uint32；每条 16 字节。centres.reshape(-1,3) 与 states.ravel() 使用相同排列顺序，因此每条标签匹配其坐标。PointCloud2 的 width=144000、height=1、point_step=16、row_step=width*16；fields 的 offset 为 0/4/8/12 字节，类型分别 FLOAT32/FLOAT32/FLOAT32/UINT32。tobytes 写入消息，is_bigendian=false 与小端格式一致。此话题包含所有状态，不能把全部点都视为障碍。

previous=[None] 在闭包中记住上次切片高度。update_slice 获取参数，高度未变则返回，避免重复构造显示消息。有效高度范围 [0,3)，floor(height/resolution) 选择包含该高度的一层；只选该层 states==FREE 的格心。切片中心是该层中心，不一定等于输入高度，比如 1.2 对应约 1.25 米格心。显示厚度 .015 米是为了看清，不代表可飞行层真的只有这个厚度。

高度越界时发布空点列表清空切片，并记录 warning。timer 每 .5 仿真秒检查参数；初次立即执行。因为这是显示更新，暂停仿真期间修改切片会等恢复时生效。spin 保持保留消息发布器存活，finally 清理。

### 15.5 测试解释与适用边界

test_voxel_map.py 的 setUpClass 生成一次地图；test_shape_and_labels 检查维度和三个标签。test_height_changes_flyability 在绿色箱子同一 XY 的 .4/1.0/1.5 米处检查实体、禁区、自由。test_boundaries 检查上界、负高度、墙附近和地板/天花板附近不可飞行。

这份地图是球心的静态可达空间约束，还不是路线。未来规划器连接相邻格、平滑路径时，仍要检查连续线段/扫掠碰撞和对角穿角，不能仅凭终点是 FREE 就直接飞过去。手动 flight_control 此阶段仍使用原先的短距离几何保护，没有偷偷加入自动规划。

`index_of` 对世界坐标换算得到的格索引先做十位小数舍入，再 floor，避免 1.2/0.1 的二进制浮点误差落到下一层；最后限制到最大合法索引。query 先检查范围再调用它，切片也共用此函数。新增测试确认 z=1.2 的索引为 12。

### 16.2 planner3d.py 逐句说明

heapq 是最小堆优先队列；numpy 处理向量；从 voxel_map 导入 build、index_of、FREE。`class Planner` 封装地图和规划。构造函数 build 读取当前 SDF 生成体素，radius 是碰撞半径加余量 .33 米。

`free(p)` 将输入转换为浮点数组；依次检查形状为三维、数值有限、位于地图半开范围内，以及所在体素为 FREE。布尔表达式短路，前面检查不通过就不访问数组索引。

`segment_clear(a,b)` 检查球心从 a 到 b 的**整条线段**。先限制两个端点位于地图边界缩进半径后的范围内；轴对齐房间是凸集合，端点在内则整段在内。d=b-a 是方向向量。

对每个障碍箱体，centre±half_size 得到 lo/hi 两个角。令 p(t)=a+t*d，t∈[0,1]。`breaks=[0,1]` 初始化端点；对每个轴计算路径穿过箱体六个面所在平面的 t，并只收集 0<t<1 的交点。方向分量为零时跳过除法。海象运算符 `t:=...` 表示计算并保存 t 后用于条件判断。

排序、去重后，相邻交点把线段分段。在每个分段中，点位于箱体哪一侧的关系不变。取中点确定 mask：在哪些轴上处于箱体之外；offset 是起点到对应箱面偏移。该段的点到箱体距离平方是二次函数，分母 dot(d[mask],d[mask]) 非零时，计算导数为零的位置，再 clip 到该段区间内。这给出候选最短距离点，而不是按固定间隔采样碰撞。

将所有分段端点和极小值候选代回 p(t)，maximum(lo-p,p-hi,0) 计算点到箱体每轴距离，norm 得到实际欧氏距离。最小距离不大于 .33 米则拒绝，全部箱体通过才返回 True。零长度线段也检查当前位置的间距。

`plan(start,goal)` 要求目标体素可飞行；起点若在保守禁区体素内，会先检查实际球体是否仍有足够间距，再尝试连接 0.5 米以内最近的最多 32 个自由体素。只有完整连接线安全，才递归从该格继续规划。这样可以从取消后的箱角安全位置重新起步，不放宽物理碰撞约束。若整条直线安全，直接返回起终点，这是最快情况。否则将两点映射到体素 s/g，创建 queue、cost、parent、closed。

queue 每项为 (总代价估计,已走步数,索引)。directions 是 ±X/±Y/±Z 六个面相邻方向，不直接对角穿过障碍角。循环弹出估计最小的格，已展开则跳过，到达目标则结束。对六邻居检查范围和 FREE；新距离比旧记录小则更新 cost、parent，并把 `new + Manhattan(v,g)` 放入优先队列。每步代价为 1，所以曼哈顿距离是该六邻接网格的可用启发式。队列耗尽而没找到目标时抛错。

从 g 沿 parent 回溯到 s，反转得到格心路径，并在两端补上实际世界起终点。路线简化从当前点尝试连接最远的后续点，只有 segment_clear 通过才跨越中间格。没有安全后继则拒绝路线。输出普通列表，便于 ROS 消息和 JSON 保存。A* 最优性针对六邻接格步数，简化后不承诺全局最短连续三维曲线。

### 16.3 navigation3d.py 逐句说明

创建 ghost_navigation3d 节点与 Planner。nav_cmd_vel 发布执行速度；/ghost/path 发布 nav_msgs/Path，/ghost/navigation_status 发布 JSON String。路径/状态使用可靠保留 QoS，晚启动 RViz/客户端也能得到最近一次信息。

state 保存最新位姿、接收时间、是否有活动目标、请求 ID 和轨迹。status() 构造含 id/status/detail 的 JSON，已有定位时补充 pose，同时打印日志。finish() 先将 active 设为 false、发布零速度，再发布终态；若有目标则把请求、路线、轨迹、最终位置、位置误差写到 navigation3d_result.json。文件保存最近一次完成任务，测试脚本另存各案例。

poses 回调寻找 ghost 模型位姿，转换 yaw 并记下实际接收时间。goal 回调若有旧任务则先取消；使用目标时间戳 sec:nanosec 作为请求 ID，便于客户端区分不同目标。

目标 frame_id 必须为 simulation_reference；定位必须在最近 .5 秒内更新。四元数要求有限、roll/pitch 分量接近零、z²+w²接近1，只接受水平朝向。提取目标 XYZ，调用 plan；yaw=2*atan2(z,w)。state.update 保存路线、下一路点索引 1、轨迹空表、开始时间和进展锚点。

构造 RosPath，复制目标 header，为每个 XYZ 路点创建 PoseStamped，orientation.w=1（此路线仅展示位置，不表达逐点机头方向）。发布路线与 ACTIVE 状态。目标不合法或找不到路线时捕获 ValueError，发零速度并发布 REJECTED。

cancel 服务使用 std_srvs/Trigger。若有活动任务就 finish(CANCELED)，否则也发布零速度；response.success=true 表示取消请求已处理，不代表此前一定有活动任务。manual 回调检测手动速度是否非零，非零输入立刻取消自动导航。

### 16.4 tick() 跟踪器逐句说明

没有活动目标就返回。定位超过 .5 秒没有更新则 FAILED。把当前实际位姿追加到轨迹；总时限 180 秒，超过就失败停车。离上个进展锚点移动超过 .08 米，更新锚点和时间；20 秒无位移进展则失败。这不是根据已发出速度判断“在运动”。

取当前路点和距离。距离小于 .045 米且后面还有点时，先检查**当前位置**到下一路点整条线段，安全才推进索引，防止提前转弯切入障碍。再检查当前实际位置到目标路点线段，不安全时停止报错，当前版本不会在线重新规划。

将目标 yaw 与当前 yaw 的差用 atan2(sin,cos) 归一化。最后一个路点位置距离小于 .06 米后停止平移，继续转头；朝向误差小于 .10 弧度才 SUCCEEDED。否则速度 v=(target-current)*min(1.2,.28/distance)：远处速度模长最多 .28 米/秒，近处按距离比例减速。yaw 速度限制在 ±.6 弧度/秒。

发布 Twist，交给下游飞行控制器继续限幅、检查局部停止保护和世界/本体转换。timer 使用 STEADY_TIME，每 .05 实际秒执行，定位/任务超时不依赖仿真时钟是否暂停。spin 处理回调，Ctrl+C 时取消任务、发零速度并清理。

### 16.5 手动/自动指令如何避免争抢

flight_control 新增 /ghost/nav_cmd_vel 订阅，沿用 /ghost/cmd_vel 作为手动输入。receive(msg,navigation=False) 区分来源：手动非零输入更新 manual_time；最近 .4 秒有手动运动则不采用导航消息。导航消息记录 nav_time；最近 .25 秒有导航输入时，忽略键盘空闲时持续发送的零速度。这样挂着键盘窗口不会导致自动飞行停停走走。

导航节点也监听手动话题，收到非零命令就取消任务，因此不会在手动停止后悄悄恢复旧路线。keyboard.py 新建取消服务客户端；按空格或 K 时发送 Trigger 请求，并在循环中 spin_once(timeout_sec=0) 处理 ROS 通信。空格仅用速度零值无法表达“取消自动任务”，因此需要这个独立服务调用。

手动输入与导航速度仍共享原有 .4 秒命令看门狗。若飞行控制器自身被强制杀死，原先关于 Gazebo 速度插件保持最后速度的限制依旧成立。

### 16.6 navigate_to.py 客户端逐句说明

argparse 接收 x/y/z 浮点数与可选 --yaw；拒绝 NaN/无穷。初始化节点、目标发布器、取消服务客户端。取当前时间作为目标 stamp/identifier。

receive 解析状态 JSON，仅记录 id 与本次目标相同的消息，防止把保留的上一次成功误认为当前成功。等待最多 10 秒直到目标订阅者和取消服务出现，再 spin 1 秒让状态订阅完成发现。

构造 PoseStamped：房间坐标、请求时间戳、位置 XYZ；sin(yaw/2)/cos(yaw/2) 写入四元数 z/w。publish 后 sent=true，最多等 190 秒。看到 SUCCEEDED 返回 0；FAILED/REJECTED/CANCELED 返回 1。超时抛异常；Ctrl+C 提示取消。

finally 在已经发目标且尚未收到终态时调用取消服务，等待最多 3 秒，再清理 ROS。取消服务作用于当前活动导航，因此它是全局“停下”接口，不是可并行管理多个飞行任务的多机器人动作系统。普通目标替换会先报告旧任务 CANCELED。

navigate.sh 设置 Humble 环境和域 43，然后将参数原样传给客户端。cancel_navigation.sh 调用固定 Trigger 服务，timeout 10 限制服务命令最长等待时间。这里不再使用小车的 NavigateToPose 动作服务。

### 16.7 显示和验证

RViz 新增 3D flight route，订阅可靠保留的 /ghost/path，用粉色 3.5 厘米宽线显示空间航线。停止后旧路线可以保留用于观察，并不意味着仍在执行。当前通过命令行明确输入高度，不使用只能选平面位置的 2D Goal Pose。

test_planner3d.py 检查直线升高、越箱路线、非法目标、长线段中段碰撞和原地目标。check_navigation3d.py 依次发送升高、箱前、箱后目标，检查服务器成功、真实误差 <.08 米、记录轨迹相邻点连线安全，以及越箱时高度确实增加；最后确认箱内目标被拒绝。离散记录验证不等于覆盖所有连续物理时刻，但控制器执行时也持续检查连线。

另已实测取消服务与非零手动指令接管：都返回 CANCELED，停止后的 1 秒观察窗口内位移为 0 米。见 sensor_samples/navigation3d_cancel_validation.json。

## 17. 大模型控制幽灵的三维目标

本阶段接入真实阶跃星辰 API。ROS、规划和执行在本机，模型推理在云端。早期章节“尚未接入大模型”是当时阶段记录；当前入口是 ghost_ai.sh，不是原小车的 robot_ai.sh。

### 17.1 使用方式与数据流

```bash

/home/ubuntu/ghost_sim/ghost_ai.sh '升高半米'
/home/ubuntu/ghost_sim/ghost_ai.sh '降到1米'
/home/ubuntu/ghost_sim/ghost_ai.sh '飞到绿色箱子正上方'
/home/ubuntu/ghost_sim/ghost_ai.sh '停下'
```

先在同一个终端设置 STEPFUN_API_KEY。使用 `read -rsp 'StepFun API key: ' STEPFUN_API_KEY; echo` 然后 `export STEPFUN_API_KEY`，输入不回显。不要把真实 key 写进 Python、JSON 或讲解文档。

自然语言 → 模型意图 JSON → 本地坐标解析 → 三维目标/路线校验 → navigate.sh → navigation3d → 飞行控制。模型不直接发速度、不生成 shell，不负责判定物理到达。成功须以导航状态 SUCCEEDED 为准。

### 17.2 文件分工

- ghost_ai_config.json：base_url 为接口根地址；llm_model 为文字模型；vision_model 为视觉模型，两者默认 step-1o-turbo-vision。配置不含 key。
- ai_client.py：HTTP 请求、响应解析、可选实时相机采图。复用已经验证过的阶跃接口形式，放在幽灵项目内独立运行。
- ghost_ai.py：幽灵三维动作语义、目标计算与执行。
- ghost_ai.sh：加载 Humble，设域 43，执行 Python 并转发参数。
- test_ghost_ai.py：离线协议与动作边界测试，不使用真实 key。

### 17.3 ghost_ai.py 导入和地标生成逐句解释

argparse 处理命令行；json 处理配置/模型输出；math 校验数字及角度；os 读取环境；subprocess 调用固定导航程序；sys 设置退出码；time 控制位姿等待。Path 找项目目录，ElementTree 读取本地 SDF。导入 ai_client 的请求/采图函数与 Planner。

ROOT 是当前脚本所在目录。STOP 集合列出无需联网即可停止的词。字符串先 strip 再 lower，所以英文大小写不敏感。

`landmarks()` 先登记 home=(0,0,1.2)。读取 ghost_room.sdf，遍历 green_box 和 orange_box。解析模型中心 x/y/z、碰撞箱尺寸 sx/sy/sz。旁边目标在 ±X 侧，距离中心 sx/2+.65 米，高度 1.2 米。上方目标保持箱子 x/y，球心 z=箱中心 z+箱高/2+.65。这些是已知地图几何，不代表模型从图像测出了坐标。当前场景箱子无旋转、碰撞链接无额外偏移；如更改这些假设需同步调整函数。

### 17.4 提示词与动作协议逐句解释

`system_prompt(places)` 返回系统提示。明确 XYZ 是米制位置，z 是球心高度，yaw 单独为弧度。只接受以下意图：

| action | 允许字段 | 含义 |
| --- | --- | --- |
| navigate | position=[x,y,z]，可选 yaw | 绝对坐标目标 |
| navigate | target=地标 ID，可选 z/yaw | 本地地标目标，可覆盖绝对高度和朝向 |
| relative | delta=[dx,dy,dz] | 相对于执行前真实位置的世界坐标位移 |
| height | z | 保持当前 XY，只改球心高度 |
| stop | 无 | 取消导航 |
| answer | text | 问答或澄清，不移动 |

提示用“升高半米”和“降到1米”区别相对与绝对高度。不指定朝向时让模型省略 yaw，由程序保留当前朝向。前后左右若未明确坐标约定，提示模型先问；多步骤或未知物体也不编造目标。json.dumps 将本地地标表附到提示，ensure_ascii=False 保留中文。

### 17.5 parse/finite/vector/resolve 逐句解释

parse 首先确认模型内容为字符串，strip 后若有完整 Markdown 围栏，去掉首末行。json.loads 失败就报错；结果必须是字典。取 action 和 keys，逐项与白名单比对。navigate 二选一 position/target，不能同时带两者或附加命令字段；relative/height/stop/answer 的键集合严格匹配。这里只验证结构，数字与目标有效性留给后续处理。

finite 使用 `type(value) in (int,float)` 排除布尔值和数字字符串，再用 math.isfinite 拒绝 NaN/无穷。vector 要求列表长度恰好为 3，对三个分量逐一调用 finite。

resolve(action,current,places) 将意图统一为 `{action:navigate,position:[x,y,z],yaw:...}`。relative 通过 zip 把当前 XYZ 与 delta 相加；height 仅替换当前 z。target 必须是已登记字符串，复制本地三维坐标，可选 z 覆盖球心绝对高度。绝对 position 直接校验使用。yaw 默认当前值，有明确参数才替换，最后 atan2(sin,cos) 归一化。

### 17.6 current_pose() 逐句解释

函数内导入 ROS 和 TFMessage，只有真正移动时才需要定位。初始化临时 ghost_ai_pose 节点，订阅 /simulation/ground_truth/poses，队列长度 1。回调只取 ghost 模型，存储平移 XYZ 和由四元数计算的 yaw。

deadline=monotonic()+8，循环 spin_once 最多等 8 秒，收到第一条新位姿后返回；没有位姿则报错，不使用上次文件里的旧位置。finally 销毁临时节点、try_shutdown。这里在 API 回复后才调用，因此“升高半米”参考的是这次动作开始前的实时高度，而非几十秒前发送模型请求时的位置。

### 17.7 main() 逐句解释

ArgumentParser 声明 command、--dry-run、--vision。明确停词先构造 stop，不检查 key、不采图、不请求模型。其他命令先检查 key 非空，读取配置、生成地标、构造 system_prompt。vision 时调用 capture_camera，否则 image=None，再调用模型并 parse。

若 --vision 返回了移动意图则拒绝；观察模式只允许回答或停止。answer 打印后结束；stop 打印后调用固定取消脚本，dry-run 时不执行取消。

其余动作先读当前位姿，再 resolve，随后 Planner().plan(current,position) 验证当前起点、目标和整条路线。无效目标或无路可走立即报错，不向导航发送请求。即使模型解析成功，这一步也可能拒绝。

record 保存原始用户任务、结构化意图、最终 XYZ/yaw、所参考的实时位姿、规划路点数量与 dry_run 标志，写入 sensor_samples/ai_goal.json，不含 API key。打印实际目标，dry-run 在此结束；注意它仍会调用模型，并非离线测试。

执行时用参数数组 `[navigate.sh,x,y,z,'--yaw',yaw]`，不经过 shell 拼接。subprocess.run 等待导航返回并透传退出码，所以导航失败不会被误报为模型任务成功。Ctrl+C 中断时，同一终端中的导航客户端也会收到中断并请求取消；还可以在另一终端执行 ghost_ai.sh 停下。

ValueError/OSError 被转换为中文失败提示和退出码 1；KeyboardInterrupt 返回 130；正常动作返回 0。main 入口通过 sys.exit 把状态交给 shell。

### 17.8 ai_client.py 和 shell 逐句解释

capture_camera 与幽灵的 /camera/image 通信，8 秒内等实时 RGB 图像，通过 CvBridge 转成 OpenCV BGR，再用 imencode 编码 JPEG，base64 编码后形成 data:image/jpeg;base64,...。finally 关闭临时 ROS 节点。图像默认不落盘。

call_model 从环境读取 STEPFUN_API_KEY；地址由环境 STEPFUN_BASE_URL 优先覆盖配置，远程要求 HTTPS，本机兼容服务可用 HTTP。有图时选 STEPFUN_VISION_MODEL，否则选 STEPFUN_LLM_MODEL，未设置环境值就用 JSON 配置。

文字请求使用 config['system_prompt']。图片请求覆盖为独立视觉提示，明确消息已经附图、只描述观察结果，不混入三维导航规则，避免之前“已经传图却叫用户使用 --vision”的问题。

消息包含 system 和 user；user 无图时为字符串，有图时为 text 与 image_url 两个内容块。payload 指定模型、temperature=0、max_tokens=600；低温度不等于模型理解绝对正确。Request 把 JSON 转 UTF-8 字节，设置 Content-Type 与 Bearer 认证头。urlopen 设置 40 秒网络超时，json.load 解码响应。

HTTP 错误仅展示状态和中文说明，不原样打印服务器响应；网络失败给出连接提示。成功返回 choices[0].message.content，字段缺失则报错。密钥从未写入提示词、任务记录或导航参数。

ghost_ai.sh 的 source 加载 ROS，export ROS_DOMAIN_ID=43 指向幽灵通信域，exec python3 指定本地 ghost_ai.py；"$@" 原样传递引号中的中文任务。与模型配置有关的 export 仍从启动它的终端继承。

### 17.9 离线测试和边界

七项测试覆盖相对/绝对高度、地标可飞行、严格动作字段、非法数值/未知目标、无模型停止、dry-run 不产生运动、视觉模式禁止移动。unittest.mock.patch 替换 API/实时位姿/执行函数，所以这些测试不产生真实飞行、不验证模型语义理解；真实联调结果另行记录。

现阶段一次执行一个目标，不支持把多步骤自然语言自动拆成任务队列。地标来自已知场景；相机问答不提供世界坐标。解析意图、目标规划、真实飞行是三次独立判断，应以最后导航终态判断是否完成。

## 18. 项目分类、统一入口和源码打包

本次只调整组织方式与路径访问，保留已有控制、体素、规划和大模型算法。第 1～17 章源码块是开发时的快照，当前路径和运行命令请以本章、README 和《目录说明》为准。

### 18.1 分类依据

src/ghost_sim/simulation 负责生成场景；control 负责即时速度和键盘；navigation 负责目标到路线再到速度；mapping 负责空间可通行数据；visualization 负责显示/TF/点云；ai 负责模型通信与意图解析。每层有空的 __init__.py，表示可导入的 Python 包。

模型和场景不是代码，放 assets；运行选项放 config；ROS 进程编排放 launch；启动脚本放 scripts；不需要仿真的测试放 tests/unit，需要实际移动的测试放 tests/integration；说明放 docs。地图、轨迹、日志、截图等运行结果放 runtime，不再和源码混放。

### 18.2 paths.py 逐句说明

`ROOT = Path(__file__).resolve().parents[2]`：从 src/ghost_sim/paths.py 向上取 ghost_sim、src、项目根目录，得到当前克隆位置，避免写死 /home/ubuntu。

WORLD、MODEL、TEMPLATE 分别指向 assets/worlds、assets/models、assets/templates 中的文件；CONFIG 和 SCRIPTS 是配置/脚本目录；REPORTS 指 runtime/reports，MAPS 指 runtime/maps。

`for directory in (REPORTS, MAPS): directory.mkdir(parents=True,exist_ok=True)` 自动创建输出目录。干净仓库和压缩包不包含旧运行数据，程序仍能直接保存新结果。

模块按需 `from ghost_sim.paths import ...`；跨功能代码使用完整包名，例如 `from ghost_sim.navigation.planner3d import Planner`。这取代了依靠所有文件碰巧在同一目录的导入方式。

### 18.3 scripts/env.sh 逐句说明

BASH_SOURCE[0] 是 env.sh 自己的路径。dirname 后进入上一层，pwd 得到 GHOST_SIM_ROOT。source /opt/ros/humble/setup.bash 加载 ROS；export ROS_DOMAIN_ID=43 保持幽灵通信域；IGN_PARTITION=ghost_sim 保持 Gazebo 分区。

PYTHONPATH 在前面添加项目 src，保留用户原有路径；因此 `python3 -m ghost_sim.navigation.navigation3d` 能定位正确模块，而不用安装到系统 Python。mkdir -p 创建日志、报告、地图目录。所有底层启动脚本 source 同一份环境，避免各自遗漏变量。

### 18.4 ghost.sh 逐句说明

先解析自身所在的项目根目录；command_name 取第一个参数，缺省为 help。shift 去掉命令名，余下参数保持原样。case 按 start/view/teleop/goto/ai/stop 分发到 scripts 中对应脚本；exec 替换进程，使 Ctrl+C 能正常传播。

package 调用打包脚本，不要求 ROS 环境。test/check-flight/check-navigation/build-model/map 先 source env.sh，再分别调用 unittest、物理验收脚本、模型生成模块或体素查询模块。help 打印命令，未知命令返回退出码 2。

例如 `./ghost.sh goto 0 0 2 --yaw 1.57` 最终通过 scripts/navigate.sh 执行三维客户端；`./ghost.sh ai '升高半米'` 保持中文任务作为一个参数。旧根目录入口移到 scripts，不重复保留文件；详细对照见《目录说明》。

### 18.5 launch 与资源路径

launch/sim.launch.py 从 paths 读取 SDF/URDF 绝对路径。普通节点由 `python3 -m ghost_sim.<分组>.<模块>` 启动，继承 env.sh 配置的 PYTHONPATH。RViz 配置改为 config/ghost.rviz，AI 配置改为 config/ghost_ai_config.json。

场景生成器写入 assets，地图生成器写入 runtime/maps，导航与 AI 结果写入 runtime/reports，集成测试同样从这些位置读取数据。已有本机运行记录已搬迁保留，未上传到远端。

### 18.6 package.sh 逐句说明

脚本先定位项目根目录，再创建 dist。tar 使用明确白名单：README.md、.gitignore、ghost.sh、src、assets、config、launch、scripts、tests、docs。排除 __pycache__、pyc、本地 .env 以及 key/pem 文件；runtime、.git 和桌面截图不在白名单中。

`-czf` 表示创建 gzip 压缩 tar 包；`-C` 让输入路径相对于项目根目录；`--transform='s,^,ghost-sim/,'` 给包内文件统一加一层目录，解压时不会把文件散到当前文件夹。输出 dist/ghost-sim-source.tar.gz。

这是源码包，不包含 ROS/Gazebo 安装包、模型 API 密钥或虚拟机系统。另一台 Ubuntu 22.04 机器仍需先安装 README 中的依赖，再运行 ghost.sh。
