# 倾斜抓取、相机同步与虚拟机性能

## 操作

先保持仿真运行：

```bash
cd /home/ubuntu/ghost_arm
./ghost.sh start gui:=true
```

另一终端执行倾斜抓取（当前默认就是 -60°）：

```bash
cd /home/ubuntu/ghost_arm
./ghost.sh grasp pick --pitch-deg -60
```

也可用 `--pitch-deg -20` 调整倾斜角，或 `--pitch-deg 0` 垂直抓取。当前地面演示只开放 -60° 到 0°；其他方向需要重新检查可达性和接触几何，不代表腕关节只能在这个区间运动。

完成后用 `./ghost.sh grasp release` 松开。仍使用仿真中的木块位姿对准，尚未实现相机识别驱动的抓取。

`pitch` 是肩、肘、腕共同决定的末端总俯仰角，并非直接把腕关节设成 -30°。程序改变末端目标姿态后重新求整条机械臂的逆解，再过滤碰撞路径。

## 为什么原来相机画面不一致

独立相机窗口标出 `STALE CAMERA` 时，它显示的是旧画面。以前仿真重启后时间戳从零开始，缓存却还保留之前较大的时间戳；按最小时间戳淘汰数据会反复删除新帧，导致无法恢复同步。

`src/ghost_sim/perception/rgbd_sync.py` 现在记录各路最新时间戳，发现时间回退就清空旧缓存；RGB、深度、CameraInfo 必须时间戳完全相同才配对。缓存按到达顺序限长，选最新完整帧。测试覆盖满缓存重启、错帧拒绝、缺失一路时有界缓存。

独立窗口的 RGB 和深度是同一时刻的配对。RViz 的两个 Image 面板各自订阅，渲染刷新不保证同一瞬间；精确像素测量以独立窗口为准。

超过 2 秒没有新配对时，独立窗口将画面遮黑并标出过期，不再把旧图当作当前图显示。仿真重启后自动恢复，不需要每次重开窗口。

深度原来固定映射 0～4 米，几十厘米范围的差异很难分辨。现在按有效深度的 2%～98% 分位数动态调整颜色范围，并显示对应的米数。颜色变化代表距离范围变化，不代表物体材质。无效深度用黑色；RViz 深度面板也启用自动范围。

## 降低负载

物理步长保持 0.002 秒不变。旧版本关节发布器每个物理步都发布，等于 500 Hz；这台 Fortress 6.16 的插件不能直接用 update_rate 参数降频。新增 `src/gazebo_plugins/joint_feedback.cc`，只把六个实测关节的位置以 50 Hz 发布给原来的桥接话题。

- `Configure()` 查找六个关节，启用 JointPosition 测量组件，并创建发布器。
- `PostUpdate()` 在物理更新后读实际角度，每 20 ms 仿真时间发一条消息。
- 发布时间按 20 ms 仿真网格对齐，维持与 PosePublisher 的精确时间戳配对，供 `fk --live` 验证。
- 仿真时间回退时重新开始发布；暂停时不重复发旧数据。
- 消息仍采用 `ignition.msgs.Model`，沿用已有 ROS 桥，控制话题不变。
- 插件当前只发布位置，不提供关节速度/力测量值，勿将这些未测量字段用于力控制。

`start_sim.sh` 自动通过 `scripts/build_plugins.sh` 编译 C++ 插件；构建目录为 `runtime/build/plugins`，日志为 `runtime/logs/plugin_build.log`。需要 `cmake`、C++ 编译器和 `libignition-gazebo6-dev` 等 Gazebo 开发依赖（本机已具备）。库搜索路径通过项目环境脚本设置，不覆盖系统安装。

此外，将 RViz 渲染限制为 5 FPS、场景标记更新降为 5 Hz、独立相机绘图限制为 10 FPS，并限制 Mesa 软件渲染线程数。传感器仍保持 320×240、5 Hz，原始深度值和内参没有为显示效果而改变。

虚拟机同时运行两个三维窗口和相机窗口仍有成本。抓取时可只开 Gazebo 与 `./ghost.sh camera`，需要查看 ROS 模型时再开 `./ghost.sh view`。也可以 `./ghost.sh start gui:=false` 配合 RViz，避免两个三维渲染窗口同时运行。

## 倾斜夹取如何避免撞地

竖直手指在抓取中心以下延伸 0.03 米，倾斜后盒子的前后边角也会降低。程序按

`0.03*cos(pitch) + 0.0225*abs(sin(pitch))`

计算最低点相对于抓取中心的高度差，将抓取中心设到保证手指离地至少 8 mm 的高度，再计算小球下降目标。两指仍沿各自 Y 轴闭合，接触摩擦负责带起木块。

这仍是固定小场景的解析 IK 加直接路径演示，不是任意姿态、任意障碍下的通用抓取规划。

## 验证

40 项单元测试通过。倾斜 -30° 的实际抓取中，木块上升约 23.7 cm，整段机械臂与球体的最小间隙约 2.2 cm。消息采样测得关节发布从 500 Hz 降至 50 Hz；一次相同三窗口负载下，仿真推进速度由约实时的 39% 提升到 59%，具体速度随窗口大小、虚拟机负载变化，并非保证实时运行。

只读流检查：

```bash
cd /home/ubuntu/ghost_arm
source scripts/env.sh
python3 tests/integration/check_rgbd_stream.py
```

检查结果保存到 `runtime/reports/rgbd_stream_check.json`。

底部相机固定安装在 base_link 上，测量只需要 `/tf_static` 中的安装外参。相机查看器已移除对动态世界 TF 的订阅，避免重启后旧世界时间缓存造成大量 TF_OLD_DATA 警告；如果以后把相机装到运动腕部，需要重新接入动态 TF。

最后一次 10 秒只读检查得到 27 组精确时间戳 RGB-D 配对、277 组关节/位姿同时间戳消息，关节发布频率为 50 Hz，仿真推进约为实时的 55%。`fk --live` 独立验证通过；底部相机像素到 base_link 坐标测量通过。时间网格修正后再次倾斜抓取通过，木块上升约 23.6 cm。

倾斜抓取后木块可能侧躺落地。重复抓取会按实际旋转矩阵计算世界轴向尺寸 `abs(R) @ SIZE`，检查中心高度是否等于当前竖直尺寸的一半，再按当前 Y 向宽度计算手指夹持位置 `(width_y-0.02)/2`。支持木块以不同平面着地、基本与世界轴对齐；不把任意滚动或任意斜放姿态当作已解决的抓取情况。

侧躺木块重复抓取实测也通过，抬升约 23.7 cm。为了允许松开落地后的小幅位移，木块演示区为以初始 XY=(0.10,0) 为中心、半径 0.30 米的范围；小球仍需在原点附近。超出演示区会明确停止，不假定整间房都能直接抓取。

## 默认角度调整为 -60°

末端默认俯仰角改为 -60°，接受范围为 -60° 到 0°。这是夹爪相对于球体的总俯仰角，不是单独将腕关节转到 -60°；肩、肘、腕由逆运动学共同计算。保持原抓取中心位置，沿用球体间隙检查及倾斜手指最低点的离地约束。之前记录的 -30° 测试仍作为历史记录保留。

-60° 实机仿真验证通过：木块实际抬升 23.55 cm，动作中的最小球体间隙约 2.20 cm；新增 -60° 路径与手指最低角点检查后，共 41 项单元测试通过。
